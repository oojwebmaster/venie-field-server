# VENIE FIELD 멀티플레이 서버

위치·이름만 중계하는 아주 가벼운 Node + WebSocket 서버입니다.
Render 무료 플랜에 그대로 올라갑니다.

```
server/
├─ server.js   WebSocket + 헬스체크 (환경변수로만 설정)
├─ room.js     방 로직 — 네트워크와 분리되어 있어 Node에서 그대로 검증됩니다
├─ badwords.js ★ src/badwords.js 와 **완전히 같아야** 합니다
├─ palette.js  ★ src/palette.js 와 **완전히 같아야** 합니다 (물감 색)
├─ spawns.js   ★ src/spawns.js 와 **완전히 같아야** 합니다 (물감 자리 · 자동 생성)
├─ test.js     그 검증
└─ package.json
```

### ★ 같은 내용이어야 하는 파일 세 개

게임은 FTP로 카페24에, 서버는 GitHub로 Render에 올라가 파일을 **공유할 수
없습니다.** 그래서 두 벌을 두되 한 글자도 달라서는 안 됩니다.
`test/wire_test.mjs`가 바이트 단위로 비교합니다.

`spawns.js`는 **손으로 고치지 마세요.** 지형을 바꿨다면
`node --import ./env.mjs test/spawn_bake.mjs`를 돌려 두 벌을 함께 다시 굽습니다.

## 왜 이렇게 가벼운가

지형이 **시드 기반 결정적 생성**이라 모든 브라우저가 같은 월드를 만듭니다.
서버가 월드를 들고 있을 필요가 없어서, 하는 일이 "누가 어디에 있는지 나눠 주기"
뿐입니다. 15명이 붙어도 초당 180KB 정도이고 메모리는 몇 MB입니다.

## 로컬에서 돌려보기

```bash
cd server
npm install
npm start          # http://localhost:8080/health 로 확인
npm test           # 방 로직 검증 (서버를 띄우지 않아도 됩니다)
```

게임 쪽 `src/config.js`에서:

```js
net: { url: 'ws://localhost:8080' }
```

로컬은 http라 `ws://`, 실제 사이트는 https라 반드시 **`wss://`** 입니다.

## Render에 올리기

1. **GitHub 저장소에 `server/` 폴더를 올립니다.** (게임 파일과 같은 저장소여도 됩니다)
2. Render → **New → Web Service** → 그 저장소 선택
3. 설정
   | 항목 | 값 |
   |---|---|
   | Root Directory | `server` |
   | Runtime | Node |
   | Build Command | `npm install` |
   | Start Command | `npm start` |
   | Instance Type | **Free** |
4. **Environment** 탭에서 환경변수를 추가합니다.

   | 이름 | 값 | 설명 |
   |---|---|---|
   | `ALLOW_ORIGIN` | `https://내사이트주소` | ★ 아래 설명 참고 |
   | `MAX_PLAYERS` | `24` | 선택 |
   | `TICK_HZ` | `20` | 선택. `config.net.sendRate`와 같게 |
   | `ITEM_COUNT` | `14` | 선택. 동시에 떠 있는 물감 수. `config.world.paint.count`와 같게 |
   | `ITEM_RESPAWN` | `60` | 선택. 먹히고 다시 나타나기까지(초) |
   | `ITEM_CLAIM_RANGE` | `12` | 선택. 이보다 멀리서 주웠다고 하면 거절(m) |
   | `ITEM_SCORE` | `1` | 선택. 아이템 하나의 점수. `config.world.paint.score`와 같게 |
   | `ADMIN_KEY` | (없음) | 선택. 순위표 기록을 지울 수 있는 열쇠. **설정하지 않으면 아무도 못 지웁니다** |

   `PORT`는 **넣지 마세요.** Render가 알아서 넣어 주고, 서버가 그 값을 씁니다.

5. 배포가 끝나면 `https://이름.onrender.com` 주소를 받습니다.
   `src/config.js`의 `net.url`에 **`wss://이름.onrender.com`** 으로 넣으세요
   (https가 아니라 **wss**).

### ★ ALLOW_ORIGIN을 꼭 넣으세요

**브라우저는 WebSocket에 CORS를 적용하지 않습니다.** 즉 서버가 직접 막지 않으면
아무나 자기 사이트에서 이 서버에 붙을 수 있습니다. 무료 플랜의 대역폭을 지키기
위해서라도 사이트 주소를 넣어 두세요. 여러 개면 쉼표로 구분합니다.

```
ALLOW_ORIGIN=https://내사이트.com,http://localhost:5500
```

## 무료 플랜에서 알아야 할 것

- **15분간 들어오는 트래픽이 없으면 잠듭니다.** 다시 깨는 데 1분쯤 걸립니다.
  다만 연결된 WebSocket에서 오는 메시지도 트래픽으로 쳐 주므로,
  **한 명이라도 접속해 있으면 잠들지 않습니다**(클라이언트가 20초마다 핑을 보냅니다).
- 그래도 첫 방문자는 최대 1분을 기다릴 수 있습니다. 그래서 게임은 **서버 없이도
  그냥 돕니다** — 혼자 걷다가 연결되면 그때부터 다른 사람이 나타납니다.
  이건 버그가 아니라 의도된 동작입니다.
- 계속 깨워 두려면 [cron-job.org](https://cron-job.org) 같은 곳에서
  `https://이름.onrender.com/health`를 **10분마다** 두드리게 하세요.
  무료 한도가 월 750시간이라 24시간 내내 켜 두어도(약 730시간) 서비스 하나는 들어갑니다.
- 무료 플랜은 배포할 때마다 주소가 유지되지만, 서비스를 지웠다 만들면 바뀝니다.
  주소가 바뀌면 `config.net.url`도 함께 고쳐야 합니다.

## 물감 아이템 — 서버가 진실을 가집니다

`Room`이 아이템을 소유하고 `server.js`의 틱 루프가 채우고 되살립니다.

```
클라이언트 ──('take', 아이디)──▶ room.takeItem()   ← 여기서 **한 번만** 승인
           ◀──('item','took')── 나에게 (연출 시작)
           ◀──('item','gone')── 나머지 모두에게 (화면에서 지움)
```

- **먼저 온 사람이 가져갑니다.** 두 사람이 같은 순간에 손을 뻗어도 승인은
  한 번뿐이라 둘 다 색이 바뀌는 일이 없습니다.
- **서버는 지형을 모릅니다.** 그럴 필요가 없도록, 물감이 놓일 수 있는 자리를
  오프라인에서 구워 `spawns.js`에 넣어 두고 서버는 **번호만** 고릅니다.
  좌표는 클라이언트가 같은 표에서 읽고, 높이만 자기 지형에서 읽습니다.
- 줍기 **판정 자체**는 각자의 브라우저가 합니다(왕복 200ms를 기다리면 손맛이
  죽습니다). 서버는 "말이 되는 거리인가"만 봅니다 — `ITEM_CLAIM_RANGE`.
- **색을 섞는 계산은 서버에 두지 않습니다.** 순수한 겉모습이고, `palette.js`를
  서버에 한 벌 더 두면 언젠가 반드시 어긋납니다. 서버는 `#rrggbb` 형식만
  확인하고 나눠 줍니다(그 문자열이 그대로 남의 화면 재질에 들어갑니다).
- 색은 스냅샷이 아니라 `welcome`/`join`/`color` 메시지로만 보냅니다.
  드물게 바뀌는 값을 초당 20번 실어 보낼 이유가 없습니다(이름과 같은 원칙).
- 일곱 색은 **가장 적은 색을 골라** 채웁니다. 무작위로 뽑으면 한 색이 통째로
  빠진 채 한참 갑니다.

검증: `npm test` — 소유권(둘이 못 먹음) · 1분 리스폰 · 거리 검사 · 색 균형 ·
아이디 중복 없음(200회) · 색 문자열 형식.

## 점수와 순위

- ★ **점수는 서버가 줍니다.** 클라이언트가 "1점 올랐어"를 보내는 구조였다면
  그건 그냥 점수 입력창입니다. 이미 획득을 한 번만 승인하고 있으므로
  (`takeItem`) 그 자리에서 `addScore`로 함께 올립니다.
- 점수 값은 **아이템이 들고 있습니다**(`it.score`, 전선의 `v`). 나중에 3점·5점짜리
  아이템이 들어와도 화면 코드는 손댈 것이 없습니다.
- 순위표는 **서버 메모리**입니다 — 사람이 나가도 그 판의 기록으로 남고,
  무료 플랜 서버가 잠들면 함께 사라집니다(게임에 저장 기능이 없습니다).
- 이름 하나당 한 줄, 더 높은 점수만 남기고, 동점이면 먼저 도달한 쪽이 위입니다.
- 점수는 **스냅샷에 넣지 않습니다.** 드물게 바뀌는 값을 초당 20번 보낼 이유가
  없습니다(이름·색과 같은 원칙).

### 기록 지우기 (`ADMIN_KEY`)

필터를 피한 비속어 닉네임 대응입니다.

★ 개발자모드는 워드프레스 관리자 쿠키로 확인하는데 **이 서버는 그 쿠키를 볼 수
없습니다**(다른 호스팅입니다). 그래서 열쇠를 따로 둡니다. 설정하지 않으면
아무도 못 지웁니다 — 빈 문자열을 인정하면 누구나 남의 기록을 지울 수 있습니다.

**이름을 막지는 않습니다.** 걸러지지 않은 비속어 닉네임뿐 아니라 시험 삼아
남긴 기록을 치우는 데에도 쓰기 때문입니다 — 막으면 그 이름을 두 번 다시 못
쓰게 됩니다. 지운 뒤에도 그 사람이 계속 놀고 있으면 다시 올라오는데,
그때 또 지우면 됩니다.

### ★ 순위표는 `baseName`으로 기록합니다

같은 이름이 동시에 접속해 있으면 **표시 이름** 뒤에 숫자가 붙습니다
(`Don` → `Don 2`) — 머리 위 이름표가 구분돼야 하기 때문입니다. 순위표까지
그 이름으로 기록하면, 껐다 켜는 사이 옛 접속이 아직 정리되지 않은 순간에
들어갔을 때 **순위표에 없던 사람이 새로 생깁니다.**

그래서 `player.baseName`(숫자가 안 붙은 원래 이름)으로 기록하고,
**그 이름의 최고 기록만** 남깁니다. 예전 점수를 넘겼을 때만 숫자가 갱신됩니다.

## 나중에 NPC를 붙일 때

`Room`의 아이템과 같은 틀을 그대로 쓰면 됩니다 — 서버 주도 틱 루프,
`spawns.js`처럼 미리 구운 자리표, 그리고 "먼저 온 사람이 가져간다"식의
단일 승인 지점.
